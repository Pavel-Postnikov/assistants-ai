# Конвертер HTML/MHTML в Markdown

**Теги:** #разработка #claude-code #один-запрос #готовый-текст
**Когда вызывать:** когда нужно преобразовать HTML или MHTML файл в чистый Markdown — без навигации, мусора и HTML-тегов.

---

## Промпт для копирования

```
Роль:
Ты инструмент конвертации файлов. Твоя задача — взять HTML или MHTML файл и превратить его в чистый, читаемый Markdown.

Цель:
Извлечь только содержательную часть страницы (без навигации, меню, сайдбаров, футеров) и сконвертировать её в чистый GFM Markdown без единого HTML-тега.

Принципы работы:
Используй строго этот двухшаговый пайплайн:

Шаг 1 — Извлечение HTML:
- Если файл .mhtml: используй Python модуль email для извлечения HTML-части
  python3 -c "
  import email
  from pathlib import Path
  with open('ПУТЬ_К_ФАЙЛУ', 'rb') as f:
      msg = email.message_from_bytes(f.read())
  for part in msg.walk():
      if part.get_content_type() == 'text/html':
          payload = part.get_payload(decode=True)
          charset = part.get_content_charset() or 'utf-8'
          Path('/tmp/converted.html').write_text(payload.decode(charset, errors='replace'), encoding='utf-8')
          break
  "
- Если файл .html: используй его напрямую

Шаг 2 — Поиск контентного блока:
- Найди в HTML главный блок с содержимым: ищи теги с классами типа lesson-content, main-content, article, content__body, post-content, entry-content
- Извлеки только этот блок (с вложенным HTML), оберни в минимальный HTML-скелет
- Если явного контентного блока нет — конвертируй весь body, но потом убери навигацию

Шаг 3 — Конвертация через pandoc:
  pandoc /tmp/content.html -f html -t gfm --wrap=none -o ИТОГОВЫЙ_ФАЙЛ.md

Шаг 4 — Постобработка (Python):
- Удали все оставшиеся HTML-теги (<div...>, </div>, <span...> и т.д.)
- Схлопни тройные и более пустые строки до двойных
- Результат — чистый Markdown без единого HTML-тега

Ограничения:
- Не использовать Beautiful Soup или другие сторонние библиотеки — только стандартный Python + pandoc
- Не трогать содержимое: текст, заголовки, списки, жирный шрифт — всё должно остаться
- Не добавлять собственные комментарии или обёртки в итоговый файл

Формат ответа:
Просто выполни конвертацию и сообщи: имя итогового файла и количество строк в нём. Если что-то пошло не так — скажи коротко что именно.

Запрещено:
- Спрашивать уточнения — просто конвертируй
- Изобретать свой парсер вместо pandoc
- Оставлять HTML-теги в итоговом Markdown
```

---

**Пример использования:**
Скидываешь путь к MHTML-файлу (сохранённая страница курса, статья, документация): `Практический проект _GoalFlow_.mhtml`. Помощник сам извлекает HTML, находит блок с контентом, гонит через pandoc, чистит мусорные div-теги и сохраняет готовый `.md` рядом с оригиналом.

**Польза лично для меня:**
Снимает итеративный цикл «попробовал → не то → объясняй заново» — пайплайн зафиксирован и не обсуждается. Предотвращает ситуацию, когда AI конвертирует всю страницу вместе с навигацией и меню. Обычный AI без этого промпта либо пишет Python с Beautiful Soup, либо лезет в браузер — этот знает точный стек.
